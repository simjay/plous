# Code and Kustomize

[Documentation](../../README.md) · [Code walkthrough](../../guides/code.md) · [Tool integrations](../README.md) · [Keymap](../../reference/keymap.md#kustomize-explore)

Code brings Files, Helm charts, Kustomize, plain Kubernetes YAML, and declared Kustomize with Helm composition into one source connection. Terraform configuration directories are detected; detailed Terraform analysis and execution remain unavailable.

For a first edit or render, follow the [Code walkthrough](../../guides/code.md). This reference covers [source setup](#open-a-source), [browsers and configuration selection](#files-and-configuration-selection), [rendering](#render), [field history](#field-history), [findings](#findings), [comparisons](#compare-snapshots), and [engine limits](#engines-and-boundaries).

Deprecated Kustomize fields appear as warnings in Render findings, with the affected file. Loading and rendering do not rewrite your configuration.

## Open a source

Choose **Workspace → Code → + Add Source**, or **+ Add Connection → Code → Source**. Enter a **Name**, then choose a local directory or Git repository. Git setup asks for the repository URL, an optional **Branch**, and an optional starting **Path**. The path focuses browsing; the full repository remains accessible. Leave Branch blank to use the remote default branch. Existing saved Git references and repository subdirectories remain intact when renaming older connections. Entering a branch replaces an older saved reference.

Local directories do not need to be Git repositories. Local setup accepts an absolute path, `~/folder`, or a path relative to the displayed directory. **Browse Folders** opens the directory picker. Saving records an absolute local path and does not execute a tool. A local checkout remains labeled **local**, even when it has a Git remote.

Adding a source starts a background scan immediately. Reopening its workspace scans saved sources once per session, including when Overview is selected. Scans run one at a time. Files shows **scan queued**, **scanning**, **scan failed**, or **scan cancelled** while applicable, and detected configurations appear in **Helm**, **Kustomize**, **Argo**, and **Flux** browsers beside **Files**. Returning to or expanding a source refreshes its captured files. **g** refreshes explicitly. Empty tool views show no configurations. A tool view is marked **refreshing** or **stale** only when it contains previously captured items and a new scan is pending, failed, or cancelled. Background scanning does not render or run source scripts.

## Files and configuration selection

Each source has five browsers. **Files** follows its folders and files. Directory badges identify the technologies inside: **H** Helm, **K** Kustomize, **A** Argo, and **F** Flux. Use **Repository root** or **Parent** to change the browsing location. Local sources stay within their configured directory.

**Kustomize** opens a directory of connected groups, even when only one exists. Each row shows a short name, source path, and counts of overlays, bases, and components. Use **/** to find a group by name or path, then click it or press **Enter** to open its dependency graph.

Each base, overlay, and component appears once. References determine relationships, including shared inputs outside an overlay's directory. Selecting an overlay highlights its included configuration; selecting a base or component highlights its consumers. Up/Down selects nodes within the open group; Left follows a consumer and Right follows an included node. **Esc Groups** or **a → Choose Group** returns to the directory. Group selection and the last selected node are retained when reopening Kustomize, which always starts at the directory. Search selects matching nodes while keeping their group visible. Following or clicking a node outside the search clears the filter. Narrow, deep, or cyclic graphs show the selected node's labeled incoming and outgoing references.

Click a node or press **Enter** to open its overview. The overview shows one source path and render status, followed by Includes, Changes here, and Used by sections where applicable. It offers **G Graph**, **r Render**, and **d Open source** actions. Graph shows only relationships. Its crossing-symbol explanation is in Help. **/** finds text in the overview; Configuration details in Actions retains the full reference information.

Helm, Argo, and Flux use grouped cards, one per row, with highlighted names, types, and paths. Helm groups local and declared external charts by source path. Argo groups Applications, ApplicationSets, and AppProjects by folder. Flux groups controller and source declarations by folder. Arrow keys select cards, **Enter** opens details, and **d Open in Files** reveals the source file. These views describe repository configuration, not live health.

Use **:r**, **:render**, **r**, or the visible **Render** action on a supported configuration in a technology view. Kustomize names the selected target and renders exactly that node with its declared dependencies. Intermediate overlays can render too. Shared bases offer **a → Render Base Only** as an explicit secondary action; components must be included by a consuming configuration. Files is for browsing and editing. A single supported target renders directly. Multiple targets open a chooser with their paths.

For a chart included by Kustomize, choose the chart alone or its including Kustomization. Selecting a card, graph node, or group never renders. External charts declared by Argo or Flux remain inspectable but have no Render action without a captured target. Argo and Flux cards can render a containing local configuration, including the declaration, when available. This does not render the controller’s remote workload; Plous does not emulate their controllers or fetch those charts during browsing.

**Files** shows a directory tree with folders first. Enter toggles a folder or opens a file, and Left/Right collapses or expands folders. **/** searches paths while preserving manual folds. Local text opens directly in Plous Editor; remote snapshots open read-only. **:w** explicitly saves, **:v** opens optional review, and **:q** closes. Unsaved drafts remain in memory while navigating views but are not restored after exit. External file changes are checked before saving.

## Render

Render opens directly on generated output. The resource table labels **Kind**, **Name**, and **Namespace**, with one generated Kubernetes object per row. Deployment and Service are object kinds, not separate views. Select a row to update its masked YAML beside the table. The YAML pane names the object and its namespace. Cluster-scoped objects are labeled; a namespaced object with no explicit namespace says **Not specified**. Compact layouts show YAML first; Left/Right or the area labels switch between resources and YAML. Enter on a field, or a field click, opens **Field History**. **y** opens the full YAML viewer. **d** or **a → Open Resource Source** opens a verified resource origin for local editing, or read-only for remote snapshots. It is a resource origin, not a claim about which file wrote every field.

**Esc** from Kustomize Graph or Render returns to the node overview, then to the group graph and group directory with their selection and search retained. Clicking another node in a scoped graph opens its overview; Back restores the graph and its original anchor. **View output** opens an existing result without rebuilding it, including an explicitly labeled stale result. Findings, field history, and documents return to their parent first. Other technology renders retain their Graph and Output controls. **More Tools** groups comparison setup, export, captured stages, and repository checks.

A render failure appears in a compact status panel within the affected node or output, with no duplicate source path. The overview offers **r Retry render** and **d Open source**. **Technical details** opens the complete masked engine diagnostic; **Open source** opens that target’s configuration. A failed retry retains successful output with a **Previous output** label. **:r** retries or renders again, reloading saved local files. Remote rendering uses the pinned snapshot until refreshed. Unsaved editor drafts are never substituted. Returning from a running Kustomize render cancels it.

Saving a local file refreshes an already rendered selected entry. Render compares the new result with the output before the edit, initially showing changed resources and lines. **a → Show Final YAML** opens the complete result; **Show Changes** returns to the comparison. A failed render preserves the prior output and comparison baseline for a retry. Saving does not switch Files to Render or replace an open editor. A save that leaves rendered resources unchanged shows **No manifest changes**. Rendering again updates the comparison while retaining its pre-edit baseline.

**a → More Tools → Captured Stages** selects output recorded during actual Kustomize builtin transformations. Each stage names its source scope and operation in execution order. A nested stage contains that source's accumulator, which may have fewer resources than the final target. Final output restores the complete render. A visible Partial capture notice identifies a reached capture limit or an unavailable snapshot; final rendered output remains complete. Stages retain masked values and are limited to 256 changed invocations or 32 MiB per build. Same-value writes, generator execution, and non-builtin finalization do not appear as stages. Plain YAML and Helm do not invent intermediate stages.

**a → More Tools → Export Rendered YAML** writes all final resources from the selected captured render to a new file. Enter a file path and press Enter to write; Esc cancels. Values are masked, existing files are never overwritten, and the export ignores list filters, comparison direction, and intermediate stage selection. Failed or stale renders must be rendered again before export. This masked export is for inspection and may not be deployable.

Standalone Helm Inputs are under **a → Helm Inputs**: release name, namespace, ordered comma-separated values file paths relative to the source root, Helm `--set` overrides, Kubernetes version, and API versions. Defaults are release `preview` and namespace `default`. Composed rendering uses the `helmCharts` declarations and values from the kustomization.

## Field history

**Field History** shows the selected field's final value and evidence. Wide layouts show YAML and evidence together; compact layouts open on evidence, with YAML available through Left/Right. The Field History area scrolls with Up/Down and page keys. Kustomize builtin changes show before/after values in observed execution order, including values later overwritten. Resource renames retain engine identity. Named list members are matched by unique names; ambiguous or changed unnamed lists remain partial. Esc returns to the resource and field that opened this detail.

**a → Trace Across All Overlays** renders every Kustomize source except components against the same captured snapshot. Left/Right selects the Entries area, whose rows show the corresponding field value or an explicit failed, stale, absent, or unmatched state. Selecting a source retains the corresponding resource and field across verified renames and reordered named lists. One failed overlay does not hide successful traces. Refresh Source captures saved changes for a later run.

Plain YAML fields can show exact original file lines. A transformer link identifies its captured configuration and a configuration line when established. **d** opens the last observed writer configuration and positions the viewer at the corresponding node in its masked preview when that node survives redaction; without field history it opens the separately labeled resource origin when available. Resource origin alone never identifies a field writer. Helm template origins remain partial. Same-value writes, generators, and changes outside captured builtin invocations do not have full writer attribution; incomplete or ambiguous histories are labeled.

## Findings

**a → View Findings** opens the selected entry’s findings. **a → More Tools → Repository Findings** explicitly widens to all analyzed entries. This combines structural findings and completed render findings in a severity, finding, and location table. Select a row to see its explanation below.

**a → Finding Entry Details** and **a → Open Finding in Render**, or the corresponding detail links, retain its source and, when available, select the exact resource and field. **a → Trace Finding Field** opens field evidence. **/** filters severity, rule, path, and message.

The **Validate All** button or **a → More Tools → Validate All Entry Points** explicitly renders eligible entries. Counts distinguish rendered, failed, stale, not rendered, omitted paths, and unsupported Terraform directories. Terraform rendering, tracing, and validation are unavailable; those views explain the limitation and keep the configuration accessible through Files.

Checks cover parser/reference errors, dependency cycles, duplicate rendered identities, mutable image references, observed patch values overwritten later, byte-identical patch files, unreferenced manifests, and unused components in the loaded scope. Unreferenced manifests may be intentional standalone entries. An overwrite finding concerns one field and does not declare the whole patch unused. A version tag is mutable; a digest pins content. No findings does not imply complete analysis or cluster health.

Use **a → Findings**, **Images**, or **Generators**, from the findings action menu. **a → Filter Category** narrows Findings to Build, Patches, Images, Generators, or Structure. **a → Filter Source** selects one source or All Sources across all three views. The source filter combines with the category and text filters; repository coverage counts remain global, while finding severity counts follow the selected source. Images lists image references from current successful renders and distinguishes digest-pinned content from mutable references. Generators lists captured Kustomize ConfigMap and Secret declarations, input paths, and keys while hiding values. It does not claim Helm template or external generator coverage.

## Compare snapshots

Press **v** and choose another entry. Both use the selected source. Each render captures and retains its required inputs; local files can change between the two captures. **a → More Tools → Compare Git Revision** instead renders the selected path at another Git Revision. **F** loads a revision for normal browsing. Comparisons appear inside Render, with side-by-side output at sufficient width and unified output in smaller areas. **a → Comparison Options** switches comparison presentation or clears it. **a → Comparison Options → Open Comparison Reviewer** opens the shared Diff Reviewer for the entire comparison, including resources absent from the selected scope.

Comparisons match unique verified source document identities before exact final identities and mask sensitive changes. Verified prefixes and namespace changes retain a resource match. Ambiguous identities remain separate and are labeled. Removed resources remain selectable in Render.

**a → Comparison Options → Swap Comparison** reverses the displayed direction without changing the selected source. **Changed Only** filters unchanged resources and lines; **All Lines** restores them. Up/Down and page keys scroll comparison rows, including removals. Enter in comparison output opens the resource YAML. Choose Show Final YAML before selecting a field for history. Comparisons do not deploy or save resources.

## Engines and boundaries

Helm rendering uses the embedded Helm 3.22 SDK. Kustomize uses the embedded Krusty API, including composed builds whose Helm charts are rendered through the Helm SDK before Kustomize transformations. No Helm, Kustomize, kubectl, or Git executable is required for these source workflows. Successful rendering does not establish cluster acceptance or workload readiness.

Composed charts can be captured under `helmGlobals.chartHome` (default `charts`). Missing charts require an explicit repository and exact version; acquisition captures their content digest before native rendering. Unavailable dependencies fail the render. `chartHome` stays inside its kustomization directory; custom `configHome` is unsupported because rendering uses private Helm settings. Native `apiVersion: builtin` transformer configurations are supported, including metadata-only `LabelTransformer` files and inline configurations. Selected inputs include the declared files used by patch, replacement and value-add transformers. Remote Kustomize bases, executable plugins, and non-builtin transformer configurations remain unavailable; the external `generators` field is also unsupported.

Discovery retains file metadata and configuration relationships, with a 32 MiB metadata allowance. It reads configuration candidates individually and releases their bodies. The file browser becomes available before configuration inspection finishes. Rendering separately captures its required inputs, limited to 4,096 files, 32 MiB total and 2 MiB per file. Helm capture applies the chart root’s `.helmignore` and Helm defaults before reading chart assets or checking their sizes, then includes selected values; Kustomize capture follows supported transitive references. Changes detected during local input capture stop the render. The result retains its exact captured inputs for later inspection.

Local and acquired Git scans honor the profile’s `.plousignore` (normally `~/.plous/.plousignore`) and `.gitignore` within the selected source, including nested repository rules and exceptions. Excluded files and directories are skipped before opening them. Git metadata is always excluded; the default profile rules also exclude dependency and cache directories such as `node_modules`. Git ignore settings outside the selected directory are not loaded. Exact selected reads and declared render dependencies bypass these scanning exclusions. Symlinks, special files and submodules produce coverage gaps. Oversized candidates remain listed but cannot be inspected. Binary chart assets can be captured for rendering; assistant text reads reject binary content. Charts with omitted inputs fail explicitly. Select a smaller scope when a reported limit is exceeded.

Code gives the assistant bounded reads of saved files and captured analysis through the [Source tool](../../reference/mcp.md#code-and-historical-evidence). It does not grant arbitrary filesystem access, rendering, or writes. Source contents and output do not enter automatic chat context, Activity, or saved sessions. There is no file watching, deployment action, or Terraform execution in Code. Opening a Kustomize graph, overview, or existing output does not render. Field-history previews and saving inputs for an already rendered entry can refresh captured output. Background source discovery does not render.

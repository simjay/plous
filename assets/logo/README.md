# Plous logo

The mark is π built from three blocks: a bar, and two tall blocks beneath it. It reads as the
letter and, for a deployment tool, as workloads sitting under a control plane.

Everything here is generated by `gen.py`. Edit that, not the SVGs — geometry, palette and surface
treatment all live in one place.

```sh
python3 gen.py                      # regenerate every SVG
sh export.sh                        # icon.svg      -> png/
sh export.sh icon-dark.svg dark     # icon-dark.svg -> png/dark/
```

## Wordmark

Exo 2 600, set at 130px with -0.02 em tracking, **outlined to a path** in `wordmark.py`.
Exo 2 is licensed under the SIL Open Font License, which permits use in a logo. Source:
<https://fonts.google.com/specimen/Exo+2>.

Only the outlines live here, not the font software, so no OFL notice ships with these files.
Confirm that in the pre-release legal check along with trademark clearance.

Because the glyphs are outlines, the lockup renders identically on every machine and needs no font
installed and no network. Do not replace the path with live `<text>`.

To change the typeface, fetch its TTF and re-bake:

```sh
python3 outline_wordmark.py path/to/Font.ttf "Family Name" 600   # rewrites wordmark.py
python3 gen.py
```

`outline_wordmark.py` needs `fontTools`. Feed it a TTF, not a WOFF2 — fontTools 4.25 mis-reads
Google's WOFF2 subsets (it rejects the transformed `glyf` table).

## Files

| File | Use |
| --- | --- |
| `icon.svg` / `icon-dark.svg` | The app icon. Light tile and dark tile |
| `mark.svg` / `mark-dark.svg` | The glyph without its tile, for documents and anywhere beside text |
| `lockup.svg` / `lockup-dark.svg` | Mark and wordmark, horizontal. Tight canvas, so it fills the box you give it |
| `icon-flat.svg` / `icon-flat-dark.svg` | No gradients or filters. Print, embroidery, and the 16px favicon |
| `icon-mono.svg` | Blocks take the surrounding `currentColor` |
| `png/`, `png/dark/` | Raster exports at 16–1024px with transparent corners |

Pick the dark files by the background the mark sits on, not by the viewer's theme: `icon.svg` on
light, `icon-dark.svg` on dark. In HTML, `<picture>` with `prefers-color-scheme` does this.

## Lockup proportions

In the lockup the mark is scaled to `MARK_SCALE` (0.80) so it stands at about 1.1x the wordmark's
height. At full size it is 1.37x, which reads as the mark shouting over the word.

Everything else is derived from that: the gap is 0.22 of the mark's width, the wordmark is optically
centred on the mark's axis, the margins match on both sides, and the canvas is sized to the content
plus a margin that clears the drop shadow. Change `MARK_SCALE` or the typeface and the lockup
re-lays out correctly — there are no hand-placed coordinates.

The canvas is tight rather than padded, so the lockup fills whatever width you set. A `width="320"`
in a README now yields a visibly larger logo than the previous padded canvas did; reduce the width
if that is too much.

## Palette

| | Blocks | Tile |
| --- | --- | --- |
| Light | `#3B82F6` → `#7C3AED` | `#FFFFFF` → `#E8EBFF` |
| Dark | `#4F8DF7` → `#9066F0` | `#1A1D2E` → `#0B0D17` |

The dark blocks are lifted rather than recoloured, so the hue identity holds while keeping contrast
against the dark ground. Single-colour stand-in for the gradient: `#4F46E5`.

## Notes

The block gradient is declared with `gradientUnits="userSpaceOnUse"` across the glyph's bounding box
so all three blocks share one continuous ramp. An `objectBoundingBox` gradient restarts in each
block, which reads as three unrelated objects.

The mark has not been cleared for trademark use. Do that before a public release or a CNCF
submission. See `.decisions/0008-logo-and-mark.md`.

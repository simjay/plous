# Working on Plous

Jae Sim governs product, design, and technical decisions. Keep durable choices current in [.decisions/](.decisions/README.md), using topic records that distinguish owner decisions from proposals. Update existing records instead of adding logs for every fix or test run.

## Repository workflow

- Work directly on `main` unless the owner requests another branch. Keep changes local; the owner handles pushes unless explicitly requested otherwise.
- Directories whose names start with `.` are local internals and must never be committed or pushed. Only the root `.github/` is permitted for CI and release workflows. Preserve unrelated local internals. Before a push, inspect both the proposed commits and current tree for prohibited paths; do not push older history containing internals.
- Use plain, specific wording. Do not use em dashes in documentation, comments, docstrings, or help text. Remove filler and comments that repeat code; retain explanations of constraints and non-obvious behavior.
- Keep `README.md` and `docs/` user-facing and aligned with implemented behavior. Keep proposals and rationale in `.decisions/`; avoid duplicate specifications and logs.

## Structure and verification

- Keep `main.go` and embedded `VERSION` under `cmd/plous`; `internal/app` owns the application. Package unit tests stay beside implementation. Executable/terminal tests and fixtures live under `tests/`. Test helpers must not enter the application binary.
- Use `make test` for all tests, with `test-unit`, `test-e2e`, `test-race`, and `test-coverage` for focused work. Run `make check` for application changes and `make dist` for packaging changes. Keep generated files out of source control.
- Verify with temporary storage or `--data-dir` and synthetic kubeconfig files. Do not alter the owner's `~/.plous`, kubeconfig, or clusters. Use local mock providers and API fixtures when possible.
- Report hosted workflows, releases, and live-provider behavior as verified only after they actually succeed.
- Plous is `0.0.1`, an early development build, not ready to ship. `cmd/plous/VERSION` is the only application version source. Do not automatically bump versions, change major/minor versions without owner direction, or create release tags. Dependency/toolchain versions are independent.

## Product boundaries

Keep the code and repository small. The owner authorized the Eino assistant, independent RLM investigation, JSONL memory, compaction, and enforced read-only tool execution from the assistant plan and original architecture. See [.decisions/README.md](.decisions/README.md) for current scope. Deployment pipelines, agent writes, and remote workspace conversion remain deferred. The disabled Remote option does not authorize server implementation.

Keep Workspace → Tool connections. Workspaces can contain multiple contexts and repositories. Preserve identities, exact revision history, older settings, general conversations, selected scopes, and drafts across restarts. Selecting or saving a connection must not change an external tool's active context or execute it.

Read the relevant current decision before changing behavior: [interface](.decisions/interaction.md), [AI](.decisions/ai.md), or [workspace location](.decisions/remote-workspaces.md). Do not revive removed TUI concepts or treat future roadmap items as implementation instructions.

## Interaction constraints

- Use simple navigation keys and named colon commands for application actions. Ctrl+R refresh/prompt restoration and Ctrl+S validation are retired. Keep only the existing terminal and text-input exceptions documented in the keymap; do not add Ctrl-based shortcuts.
- Application action aliases use one case-sensitive letter. Use uppercase when lowercase is occupied; do not add multi-letter action aliases. Lead hints with the single key or colon alias; full names are optional. The reserved double-key navigation sequences, established editor sequences such as gg/dd/:wq, and Kubernetes resource names/abbreviations are separate. Keep application aliases in internal/app/commands.go and resource actions in their action registry; test collisions and displayed commands.
- Keep the three panels, three evenly distributed tabs (Overview, Explore, Activity), bottom composer, context estimate, and single footer. Do not restore a Main heading, Deployment mode, or General chat sidebar entry.
- Colon commands work globally in navigation. Modes use `:1`–`:3` or `11`/`22`/`33`; single numbers and mode word/letter aliases do not switch modes. Other commands have explicit short/full spellings. Use `:b`/`:sidebar` and `:i`/`:aiinteraction`; old left/right aliases remain retired.
- Reserve `bb`, `ii`, `ss`, `cc`, `hh`, `11`, `22`, `33`. The second consecutive key runs the shortcut without a timeout. Show the prefix in the existing footer; clear it on Esc, intervening input, focus changes, resize, or paste. A different reserved key starts its own sequence. Prefixes are not saved.
- Text and paste in fields or active chat remain literal. Paste in navigation or command input is ignored. Form action buttons accept commands and shortcuts without submitting edits. Commands must not discard an unfinished form in another panel.
- Colon input uses a bordered box at the bottom of main. Esc restores originating focus. Tab can resume a draft outside overlays; a fresh colon from another panel or a completed shortcut replaces it.
- Tab/Shift+Tab switch visible panels outside overlays. Settings and Help ignore both keys, including forms and command input. Hiding a focused panel moves focus to main. Panel visibility persists; chat commands reveal the assistant.
- Keep one centered Settings overlay with Application and Current workspace controls, using the tree, `ss`, or `:s`/`:settings`. Workspace + Add tool, Kubernetes + Add context, and empty Overview Enter open shared tool setup in the same modal frame. Kubernetes setup keeps an editable path (initially `~/.kube/config`) and its contexts in one view. Load that file on opening; editing the path clears selections and requires Refresh contexts before adding. Setup forms cancel to their preceding picker; Settings forms cancel to Settings. Closing a root restores its entry point. No separate config route.
- Keep Help's workspace/view/chat sections above its static global box. The view section shows controls for the current screen. Left/Right selects upper sections independently of underlying focus; arrows and page keys scroll. Help can overlay Settings and must restore its unfinished form. Preserve drafts and responses.
- `:c`/`:chat` or `cc` enters typing from any navigation panel, Help, history, or form action, even before workspace creation. Opening the composer must not depend on flushing storage. Enter sends; Shift+Enter or Ctrl+J adds a newline. Esc keeps the draft and running response. Use `:C`, `:H`, and `:X` for new/history/stop, with their full names in the [keymap](docs/keymap.md).
- `/` opens search in the focused navigation panel. Tree, Activity, and chat history filter locally; details and chat find text; resource tables retain their applied filter editor. Esc closes search before leaving its view. Text and paste in search are literal; chat/form typing and `/model` keep their existing behavior. Text find uses Enter to finish typing and n/N to move between matches; list searches still use Enter to open. Search is transient. Keep automatic tree expansion separate from manual opens/folds. See the interface decision and keymap.
- Backspace clears only the applied text filter in resource-table navigation; show that hint in its search bar. Preserve namespace, labels, sorting, selection, and Esc behavior. Backspace still deletes characters in editors. Resource types use sidebar search, direct commands, or `:k`/`:kinds`; `o` is only the labeled Pod container chooser, not a table shortcut.
- Plous Editor owns its document keys in Normal, Insert, and Select, including reserved app prefix letters. Normal/Select colon opens app commands; Insert colon is literal. Esc leaves Insert/Select for Normal, then focuses editor actions. Closing modified text offers Keep editing or Discard changes; editor-local `:q!` explicitly discards. In the focused editable document/review, `:w` validates and saves directly, `:wq` saves and closes after success, `:v` optionally reviews without saving, and `:q` closes the document. Unchanged `:wq` closes without a request. `:quit` always exits Plous. Tab indents in Insert; Normal/Select Tab and Shift+Tab move panels. Help and chat preserve the in-memory document and undo history.
- Plous Diff Reviewer returns identity-bound decisions; callers own validation and writes. Save uses :w in both editor and optional review. Enter in comparison navigation never submits. Writes require explicit Save intent and the exact validated draft and target; review saves also require a matching comparison identity. Failed saves stay in the editor with the draft and full error accessible. Show Saved to Kubernetes only after success and Save result unknown for an unconfirmed write. Log Viewer review does not pause collection or remote processes. See [.decisions/logging-and-editor.md](.decisions/logging-and-editor.md).
- Ctrl+C saves and exits everywhere, including forms, command input, overlays, and small terminals. It never applies unsaved form edits.

## AI constraints

Use Eino with OpenAI/Anthropic, vendor-and-key setup, multiple saved connections, and the maintained catalog in `internal/ai/models.go`. The owner explicitly authorized replacing the previous chat implementation without backward-compatibility logic. Use text replies, `conversation.jsonl` and `reasoning.jsonl`; do not restore Fantasy, structured-output compatibility, old chat loading, or the retired sharing flag. Advanced options remain optional.

`/model` or `/m` opens the picker only when freshly typed as the entire draft and submitted. Pasted/restored drafts remain literal; `//model` and `//m` escape commands. Group models by vendor/connection and mark the saved selection with a checkmark. Settings has no model-selection badge.

All AI work uses one persisted application-wide model selection, captured at operation start. Do not reintroduce task-specific mappings, model discovery, manual IDs, or a Settings model picker. Setup defaults do not override saved selections or provide request fallbacks. Unsupported historical selections require an explicit replacement and must remain readable.

Store API keys separately in private `credentials.json`. Never include them in revisions, conversations, sessions, or errors. Environment references remain a supported credential source. Capture workspace, connection, page identity, and namespace at operation start. General chat has no workspace scope. Read live data only through the guarded executor; enforce each tool's deterministic read policy for direct and recursive calls. RLM must not bypass the executor through host I/O or shell access. Keep complete records when compacting active Q&A. The context meter is a local estimate, with no counting API call. Full behavior and rationale are in [.decisions/ai.md](.decisions/ai.md).

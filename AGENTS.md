# Working on Plous

Jae Sim governs product, design, and technical decisions. Keep durable choices current in [.decisions/](.decisions/README.md), using topic records that distinguish owner decisions from proposals. Update existing records instead of adding logs for every fix or test run.

## Repository workflow

- Work directly on `main` unless the owner requests another branch. Keep changes local; the owner handles pushes unless explicitly requested otherwise.
- Directories whose names start with `.` are local internals and must never be committed or pushed. Only the root `.github/` is permitted for CI and release workflows. Preserve unrelated local internals. Before a push, inspect both the proposed commits and current tree for prohibited paths; do not push older history containing internals.
- Use plain, specific wording. Do not use em dashes in documentation, comments, docstrings, or help text. Remove filler and comments that repeat code; retain explanations of constraints and non-obvious behavior.
- Keep `README.md` and `docs/` user-facing and aligned with implemented behavior. Keep proposals and rationale in `.decisions/`; avoid duplicate specifications and logs.

## Structure and verification

- Keep `main.go` and embedded `VERSION` under `cmd/plous`; `internal/app` owns the application. Package unit tests stay beside implementation. Executable/terminal tests and fixtures live under `tests/`. PlousBench has its own top-level `benchmark/` toolkit, fixtures, and README; its production-tool integration stays in `benchmark/integration/*_test.go`. Shared custom views live in `internal/ui`; feature controllers live in `internal/app/{chat,monitor,code,settings,activity}`. Source acquisition and cross-tool composition live in `internal/source`. Each of Kubernetes, Helm, Kustomize, Argo, and Flux owns `internal/integrations/<tool>/{monitor,code,common}`. Monitor and Code must not depend on each other; common must not depend on either surface. Keep tool schema rules in their owning integration, and conversation storage in `internal/ai/history`. Test helpers must not enter the application binary.
- Follow the [shared design principles](.decisions/repository-structure.md#design-principles): one owner per domain rule, typed facts through presentation, one agent-authority boundary, one active input owner, and shared measured layout. New abstractions must remove duplication or enforce a boundary; switch consumers and remove the old path together.
- Use `make test` for all tests, with `test-unit`, `test-e2e`, `test-race`, and `test-coverage` for focused work. Run `make check` for application changes and `make dist` for packaging changes. Keep generated files out of source control.
- Verify with temporary storage or `--data-dir` and synthetic kubeconfig files. Do not alter the owner's `~/.plous`, kubeconfig, or clusters. Use local mock providers and API fixtures when possible.
- Report hosted workflows, releases, and live-provider behavior as verified only after they actually succeed.
- Plous is `0.0.1`, an early development build, not ready to ship. `cmd/plous/VERSION` is the only application version source. Do not automatically bump versions, change major/minor versions without owner direction, or create release tags. Dependency/toolchain versions are independent.

## Product boundaries

Keep the code and repository small. Use one simple Eino main agent with integration-owned Go projections and direct history tools. RLM, recursive agents, worker models and multi-agent orchestration are retired. Focus on tool reliability and quality before adding agent logic. Settings selects Plous, Claude Code or Codex for the right assistant panel, using the same Plous tools. Application lists Agent first, then Mouse support. Provider connections belong inside Agent with Plous selected; external agents show only native setup status. Browsing agent choices or saving providers does not switch the active agent. Provider forms return to the pending Agent choice. External agents present their own interactive terminal UI through a PTY; do not recreate their composer, transcript or menus. Fresh installations default to Plous; explicit selections persist across restarts. Claude Code and Codex must run the user's installed executables with their own setup and authentication. Do not bundle or install them, or silently switch agents when an executable is unavailable. Do not restore CLM, model editing of active.md, deployment pipelines or agent writes. Remote workspace conversion is also deferred; the disabled Remote option does not authorize server implementation.

Start with Current Workspace, using the terminal kubeconfig for Monitor and the captured launch directory for Code, with saved Workspace → Monitor/Code → Connection → tool/file views under Workspaces, with Overview, Explore, and Activity as the main tabs. Workspaces can contain multiple contexts and repositories. Current Workspace and saved connections use the same tree, navigation, selection styling, and discovery. Keep launch-directory Code history independent of the selected cluster and scan it only when opened or refreshed. Kubernetes is always available; show Helm only after detecting release metadata, and discover Argo and Flux through their APIs. Kubernetes and Helm share a cluster connection; preserve legacy connection identities. Preserve identities, exact revision history, settings, selected scopes and current conversations across restarts. The owner authorized discarding earlier development chat histories and drafts without migration. Selecting or saving a connection must not change an external tool's active context or execute it.

Read the relevant current decision before changing behavior: [interface](.decisions/interaction.md), [AI](.decisions/ai.md), or [workspace scope](.decisions/current-context.md) or [integrations](.decisions/integrations.md). Do not revive removed TUI concepts or treat future roadmap items as implementation instructions.

## Interaction constraints

- Use simple navigation keys and named colon commands for application actions. Ctrl+R refresh/prompt restoration and Ctrl+S validation are retired. Keep only the terminal and text-input exceptions documented in the keymap, including forwarded clipboard shortcuts; Ctrl+] toggles agent focus; do not add other Ctrl-based navigation shortcuts.
- Application action aliases use one case-sensitive letter. Use uppercase when lowercase is occupied; do not add multi-letter action aliases. Lead hints with the single key or colon alias; full names are optional. The reserved double-key navigation sequences, established editor sequences such as gg/dd/:wq, and Kubernetes resource names/abbreviations are separate. Keep application aliases in internal/app/commands.go and resource actions in their action registry; test collisions and displayed commands.
- Keep the three panels, three evenly distributed tabs (Overview, Explore, Activity), bottom composer, context estimate, and single footer. Do not restore a Main heading, Deployment mode, or General chat sidebar entry.
- Colon commands work globally in navigation. Modes use `:1`–`:3` or `11`/`22`/`33`; single numbers and mode word/letter aliases do not switch modes. Other commands have explicit short/full spellings. Use `:b`/`:sidebar` and `:i`/`:aiinteraction`; old left/right aliases remain retired.
- Reserve `bb`, `ii`, `ss`, `cc`, `hh`, `ff`, `11`, `22`, `33`. The second consecutive key runs the shortcut without a timeout. Show the prefix in the existing footer; clear it on Esc, intervening input, focus changes, resize, or paste. A different reserved key starts its own sequence. Prefixes are not saved.
- Text and paste in fields or active chat remain literal. Paste in navigation or command input is ignored. Form action buttons accept commands and shortcuts without submitting edits. Commands must not discard an unfinished form in another panel.
- Colon input uses a bordered box at the bottom of main. Esc restores originating focus. Alt+Left/Right can leave and resume a draft, including inside overlays; a fresh colon from another panel or a completed shortcut replaces it.
- Alt+Left/Right move to the previous/next panel globally, wrapping through visible panels before any component input or PTY forwarding. Accept Mac Escape+b/f encodings too; Alt+B/F therefore share these host shortcuts. They work in typing, editors, forms, pickers, terminals, overlays and small terminals. Park Help and Sources when leaving their panel and restore them on return without losing state. Tab toggles tree/main during ordinary navigation, revealing a hidden tree and restoring main fullscreen. It never enters or leaves the agent. Shift+Tab never switches panels. Forms, searches, command input, editable documents, Help, Sources and native terminals keep local Tab behavior. Hiding a focused panel moves focus to main. Panel visibility and assistant size persist; chat commands reveal the assistant. `ii` or `:i` cycles normal, double width, hidden, then normal. Double width keeps at least 24 columns for main. Ctrl+] focuses the agent, revealing it if hidden, and returns to the previous sidebar or main panel on the next press. Preserve drafts, forms, command input, parked overlays and native sessions. A hidden return panel falls back to main. Captured Exec retains its Ctrl+] output-review escape. Main fullscreen preserves the assistant size.
- `:f` / `:fullscreen` / `ff` temporarily expands main from any navigation panel in every view. Keep expansion across navigation within main; restore on the same command, panel focus changes, or explicit panel toggles. Esc handles local search, selection, input, and prompts before restoring layout. Help and Settings preserve expansion underneath. Do not change saved panel visibility. Editable document keys retain ownership; YAML keeps `z` for selection and supports `ff` for fullscreen. Captured Exec and text input keep literal keys.
- Keep one centered Settings overlay with Application and Current workspace controls, using the tree, `ss`, or `:s`/`:settings`. Workspace + Add connection, Monitor + Add context, Code + Add source, and empty Overview Enter open shared tool setup in the same modal frame. Kubernetes setup keeps an editable path (initially `~/.kube/config`) and its contexts in one view. Load that file on opening; editing the path clears selections and requires Refresh contexts before adding. Setup forms cancel to their preceding picker; Settings forms cancel to Settings. Closing a root restores its entry point. No separate config route.
- Keep Help's workspace/view/chat sections above its static global box. The view section shows controls for the current screen. Left/Right selects upper sections independently of underlying focus; arrows and page keys scroll. Help can overlay Settings and must restore its unfinished form. Preserve drafts and responses.
- `:c`/`:chat` or `cc` enters typing from any navigation panel, Help, history, or form action, even before workspace creation. Opening the composer must not depend on flushing storage. Enter sends; Shift+Enter or Ctrl+J adds a newline. Esc keeps the draft and running response. Use `:C`, `:H`, and `:X` for new/history/stop, with their full names in the [keymap](docs/reference/keymap.md).
- Chat navigation uses `[`/`]` to select replies and Enter to open Sources; typing keeps literal keys and Enter sends. Sources uses saved turn-bound reads only. Esc restores the reply, scroll, and draft. Keep routine per-reply metadata in details and meaningful scope limitations in answers.
- `/` opens search in the focused navigation panel. Tree, Activity, and chat history filter locally; details and chat find text; resource tables retain their applied filter editor. Esc closes search before leaving its view. Text and paste in search are literal; chat/form typing and `/model` keep their existing behavior. Text find uses Enter to finish typing and n/N to move between matches; list searches still use Enter to open. Search is transient. Keep automatic tree expansion separate from manual opens/folds. See the interface decision and keymap.
- Backspace clears only the applied text filter in resource-table navigation; show that hint in its search bar. Preserve namespace, labels, sorting, selection, and Esc behavior. Backspace still deletes characters in editors. Resource types use sidebar search or direct commands; the resource heading and table Esc reveal the sidebar; `o` is only the labeled Pod container chooser, not a table shortcut.
- Plous Editor owns its document keys in Normal, Insert, and Select, including reserved app prefix letters. Normal/Select colon opens app commands; Insert colon is literal. Esc leaves Insert/Select for Normal, then focuses editor actions. Closing modified text offers Keep editing or Discard changes; editor-local `:q!` explicitly discards. In the focused editable document/review, `:w` validates and saves directly, `:wq` saves and closes after success, `:v` optionally reviews without saving, and `:q` closes the document. Unchanged `:wq` closes without a request. `:quit` always exits Plous. Tab indents in Insert; Alt+Left/Right move panels in every editor mode. Help and chat preserve the in-memory document and undo history.
- Plous Diff Reviewer returns identity-bound decisions; callers own validation and writes. Save uses :w in both editor and optional review. Enter in comparison navigation never submits. Writes require explicit Save intent and the exact validated draft and target; review saves also require a matching comparison identity. Failed saves stay in the editor with the draft and full error accessible. Show Saved to Kubernetes only after success and Save result unknown for an unconfirmed write. Log Viewer review does not pause collection or remote processes. See [.decisions/interaction.md](.decisions/interaction.md).
- Ctrl+C goes to the focused, captured Claude Code or Codex terminal for its native interrupt behavior. Everywhere else, including forms, command input, overlays, and small terminals, it saves and exits without applying unsaved form edits. From native input, use Ctrl+] then Ctrl+C to exit Plous.

## AI constraints

Use Eino with OpenAI/Anthropic, vendor-and-key setup, multiple saved connections, and the maintained catalog in `internal/ai/model/models.go`. The main loop in `internal/ai/run.go` uses native ordered exchanges, recent completed context and host-triggered compaction. It consumes the standard-library-only `internal/ai/agent.Tools` contract; `tool_session.go` owns scope enforcement, serialized calls, persistence-before-delivery and turn lifetime. Keep provider objects out of that contract. The standard-library-only `agent.Backend` contract runs Eino. Native CLI sessions in `internal/ai/cli` use the same guarded tool contract through MCP. UI tools use the session-bound `agent.UI` port; only the app loop applies prepared views. Preserve focus and edits, reject scope changes and late navigation, and store UI receipts outside searchable resource evidence. Settings changes require closing an active native session. Saving a different agent performs that closure and evidence save before applying the choice. Keep native input in the terminal, with Alt+Left/Right for direct panel travel, Ctrl+] to toggle focus between the agent and the previous panel, and Ctrl+C forwarded to the focused native terminal. Ctrl+] then Ctrl+C saves and exits Plous. Native capture must keep mouse reporting active: clicking other panels moves focus, and clicking the native panel resumes input in the same session. Capture scope at session start and keep it fixed until closure. Preserve tested launch controls and native authentication without an exact Codex version allowlist. Native sessions have no Plous-imposed deadline or session-wide tool-call cap. Fatal tool failures revoke tool access without closing the CLI. Explicit session closure and application exit stop the process; model usage and spending remain CLI-managed. See the AI decision. Integration projectors own acquisition and mechanical Go facts. Raw API responses are transient. Preserve original conversation JSONL format; reasoning stores only projected tool observations. Requests, native checkpoints and usage belong to execution records outside searchable evidence. Preserve Sources and incomplete observations across restart. Earlier development histories are discarded. Do not retain historical chat readers, migrations, raw-record adapters or retired benchmark replay. Do not restore CLM, Bash context editing, raw-result digestion, mandatory seeding or pre-Eino chat loading. Advanced options remain optional.

With Plous selected, `/model` or `/m` opens the picker only when freshly typed as the entire draft and submitted. Pasted/restored drafts remain literal; `//model` and `//m` escape commands. Group models by vendor/connection and mark the saved selection with a checkmark. Settings has no model-selection badge.

Plous model work uses one persisted application-wide model selection, captured at operation start. Do not add general task-specific mappings, arbitrary chat model IDs, model discovery or a Settings model picker. Embed prompts and use the private compiled Go capability registry. Main and compaction share a turn-level call/token/time allowance. Context follows selected model capacity and includes the whole provider request.

Main calls bounded history search, selected reads, turn windows and deterministic typed calculations directly. No raw JSONL scanning, original API body access, filesystem fallback or interpreter. Invalid model arguments get corrective feedback; history integrity/scope, cancellation and exhausted-budget failures stop execution. Runtime configuration contains only turn budgets and optional embedding settings; reject retired history_mode and rlm settings explicitly.

History indexes follow durable commits. Monitor uses lexical and explicitly configured semantic retrieval; Code and General use lexical only. Do not semantically index repository contents. Embedding configuration is separate from chat selection, and unavailable embeddings must not block saving or live answers. Report lag and incomplete coverage. Search matches are not counts; calculations use typed observations with explicit completeness. Setup defaults never override saved selections or provide request fallbacks. Unsupported historical selections remain readable and require explicit replacement.

Store API keys separately in private `credentials.json`. Never include them in revisions, conversations, sessions, or errors. Environment references remain a supported credential source. Capture only the currently selected connection and current-page hint at operation start. Restrict live reads and model history to that captured connection or source. The viewed namespace is page context, not an access boundary; cluster reads may use any namespace allowed by Kubernetes credentials. Kubernetes and Helm share one cluster scope. Only current general and connection-scoped histories are supported; older workspace-wide chats are discarded. General chat and history-only views grant no connection tools. See [.decisions/current-context.md](.decisions/current-context.md) for startup, target capture, and persistence. Main external reads use the guarded executor and each tool's deterministic read policy. History access enforces the captured scope and committed record boundary in Go, without arbitrary file access. Keep original conversation messages and projected observations when compacting active context. The Plous context meter is a local estimate, with no counting API call; external agents report CLI-managed context. Full behavior and rationale are in [.decisions/ai.md](.decisions/ai.md).
